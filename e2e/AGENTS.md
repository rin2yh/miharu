# Playwright E2E テストの指針

このディレクトリのテストは、利用者が行う操作と画面に現れる結果を確認する。

## ロケーター

- `getByRole`、`getByLabel`、`getByText` など、アクセシビリティと画面上の意味に基づくロケーターを優先する。
- CSS クラス名、`className`、DOM の階層、`nth()`、XPath を使って要素を特定しない。
- キーボード操作や時刻属性の確認など、ネイティブ要素自体が対象になる場合は `summary` や `time` のタグ名ロケーターを使ってよい。
- アクセシブルな名前で対象を特定できない場合に限り、`data-testid` の追加を検討する。追加する属性は見た目やスタイルのために使わない。
- 共通の操作とロケーターは Page Object に置き、シナリオ固有の期待値はテストに残す。

## テストデータと独立性

- API 応答は fixture で固定し、外部サービスや実運用データに依存させない。
- 各テストは単独で実行できるようにし、テスト間の実行順や共有状態に依存させない。
- 日時や状態は fixture で明示し、現在時刻やネットワークの揺れで結果が変わらないようにする。

## 待機とアサーション

- `expect(locator).toBeVisible()` など Playwright の自動待機付きアサーションを使う。
- 固定時間の `waitForTimeout` や、画面更新が続くアプリでの `networkidle` 待機を使わない。
- 内部状態ではなく、利用者に見える結果を確認する。たとえば開閉操作は本文の表示・非表示で確かめる。
- CSS 計算値や DOM 評価は、横スクロールやテーマ色など、利用者に見えるレイアウト条件を直接確認するときに限る。

## 操作と保守

- 開閉、検索、手動更新などの操作は、マウスだけでなくキーボードでも確認する。
- モバイル表示やダークモードに関わる変更では、対象の表示幅・テーマで崩れがないことを確認する。
- テスト名は検証する利用者の行動と結果を表す。独立した振る舞いは別のテストに分ける。
- スナップショットやスクリーンショットは、差分を継続的にレビューする仕組みがある場合に使う。
- 実行は `pnpm e2e` を使う。
